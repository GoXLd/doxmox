Summary

Overview: Proxmox VE 8.2 introduces three new command‑line options for HA rule management: --affinity, --comment, and --disable. These options give operators finer control over resource placement, documentation, and rule activation.

Assessment: The addition of --affinity (positive/negative) is a significant functional change that can affect HA cluster stability if mis‑configured, so it warrants careful review. Re‑adding --comment and adding --disable improve usability and operational safety but have lower risk. Documentation updates round out the release.

Change List

  1. HighNew --affinity option for HA‑rule commands
    All HA‑rule commands (create, set, modify) now accept "--affinity <positive|negative>". The default is "positive". Positive affinity forces listed resources to run on the specified nodes, while negative affinity forces them to avoid those nodes.
    Impact: Changes how the cluster schedules resources; incorrect settings can cause VMs to be placed on undesired nodes or prevent failover.
    Action: Review existing HA rules and explicitly set the desired affinity. Test the new setting in a non‑production environment before applying to critical services.
  2. MediumRe‑added --comment option for HA‑rule commands
    "--comment <string>" is now available again in the option list for HA‑rule create, set, and modify commands, allowing operators to attach a free‑form description to each rule.
    Impact: Improves rule documentation and makes troubleshooting easier, with no effect on rule execution.
    Action: Add meaningful comments to all HA rules to aid future maintenance and audits.
  3. MediumNew --disable option for HA‑rule commands
    "--disable <boolean>" can be used to enable (false) or disable (true) an HA rule without deleting it.
    Impact: Allows temporary suspension of a rule, reducing the need for rule recreation and minimizing configuration drift.
    Action: Use "--disable true" to pause a rule during maintenance, and re‑enable it with "--disable false" when work is complete.
  4. LowDefault affinity set to positive
    If the "--affinity" flag is omitted, the system now assumes a positive affinity, preserving backward compatibility with earlier releases where only positive placement was possible.
    Impact: Existing scripts that omit the flag will continue to behave as before, but administrators should be aware of the implicit default.
    Action: Explicitly specify "--affinity" in automation scripts to avoid ambiguity.
  5. LowUpdated CLI help and man pages for HA‑rule options
    The command‑line help output and manual pages now list the new options (--affinity, --comment, --disable) and clarify default behaviors.
    Impact: Operators receive accurate guidance directly from the CLI, reducing the chance of misconfiguration.
    Action: Run "pve-ha-manager --help" or consult the updated man pages after upgrading.

Summary

Overview: Proxmox VE 8.2 introduit trois nouvelles options en ligne de commande pour la gestion des règles HA : --affinity, --comment et --disable. Ces options offrent aux opérateurs un contrôle plus fin sur le placement des ressources, la documentation et l’activation des règles.

Assessment: L’ajout de --affinity (positif/négatif) constitue un changement fonctionnel important qui peut affecter la stabilité du cluster HA s’il est mal configuré, il nécessite donc un examen attentif. La réintroduction de --comment et l’ajout de --disable améliorent l’utilisabilité et la sécurité opérationnelle, mais présentent un risque moindre. Les mises à jour de la documentation complètent la version.

Change List

  1. ÉlevéNouvelle option --affinity pour les commandes de règle HA
    Toutes les commandes HA‑rule (create, set, modify) acceptent désormais « --affinity <positive|negative> ». La valeur par défaut est « positive ». L'affinité positive oblige les ressources listées à s'exécuter sur les nœuds spécifiés, tandis que l'affinité négative les contraint à éviter ces nœuds.
    Impact: Modifie la façon dont le cluster planifie les ressources ; des paramètres incorrects peuvent entraîner le placement des VM sur des nœuds indésirables ou empêcher le basculement.
    Action: Examinez les règles HA existantes et définissez explicitement l'affinité souhaitée. Testez le nouveau paramètre dans un environnement non‑production avant de l'appliquer aux services critiques.
  2. MoyenOption --comment réajoutée aux commandes HA‑rule
    « --comment <string> » est de nouveau disponible dans la liste des options pour les commandes HA‑rule create, set et modify, permettant aux opérateurs d’attacher une description libre à chaque règle.
    Impact: Améliore la documentation des règles et facilite le dépannage, sans aucun impact sur l'exécution des règles.
    Action: Ajoutez des commentaires pertinents à toutes les règles HA afin de faciliter la maintenance et les audits futurs.
  3. MoyenNouvelle option --disable pour les commandes HA‑rule
    "--disable <boolean>" peut être utilisé pour activer (false) ou désactiver (true) une règle HA sans la supprimer.
    Impact: Permet la suspension temporaire d’une règle, réduisant le besoin de recréation de règle et minimisant la dérive de configuration.
    Action: Utilisez "--disable true" pour mettre en pause une règle pendant la maintenance, et réactivez‑la avec "--disable false" une fois le travail terminé.
  4. FaibleAffinité par défaut définie sur positive
    Si le drapeau « --affinity » est omis, le système suppose désormais une affinité positive, préservant la compatibilité descendante avec les versions antérieures où seul le placement positif était possible.
    Impact: Existing scripts that omit the flag will continue to behave as before, but administrators should be aware of the implicit default.
    Action: Spécifiez explicitement "--affinity" dans les scripts d'automatisation pour éviter toute ambiguïté.
  5. FaibleMise à jour de l'aide CLI et des pages de manuel pour les options de règle HA.
    The command‑line help output and manual pages now list the new options (--affinity, --comment, --disable) and clarify default behaviors.
    Impact: Les opérateurs reçoivent des instructions précises directement depuis la CLI, réduisant le risque de mauvaise configuration.
    Action: Exécutez « pve-ha-manager --help » ou consultez les pages de manuel mises à jour après la mise à niveau.

Summary

Overview: Proxmox VE 8.2 вводит три новых параметра командной строки для управления правилами HA: --affinity, --comment и --disable. Эти параметры предоставляют операторам более тонкий контроль над размещением ресурсов, документированием и активацией правил.

Assessment: Добавление параметра --affinity (положительного/отрицательного) представляет собой значительное функциональное изменение, которое может повлиять на стабильность кластера HA при неправильной настройке, поэтому требует тщательного рассмотрения. Возврат параметра --comment и добавление --disable повышают удобство использования и эксплуатационную безопасность, но несут меньший риск. Обновления документации завершают выпуск.

Change List

  1. ВысокаяNew --affinity option for HA‑rule commands
    Все команды HA‑rule (create, set, modify) теперь принимают параметр "--affinity <positive|negative>". По умолчанию — "positive". Положительная аффинность заставляет перечисленные ресурсы работать на указанных узлах, а отрицательная аффинность заставляет их избегать этих узлов.
    Impact: Изменяет способ, которым кластер планирует распределение ресурсов; неверные настройки могут привести к размещению ВМ на нежелательных узлах или препятствовать переключению (failover).
    Action: Проверьте существующие правила HA и явно задайте требуемую аффинити. Протестируйте новую настройку в непроизводственной среде перед применением к критическим сервисам.
  2. СредняяСнова добавлен параметр --comment для команд HA‑rule.
    «--comment <string>» теперь снова доступен в списке опций команд HA‑rule create, set и modify, позволяя операторам прикреплять свободное описание к каждому правилу.
    Impact: Улучшает документацию правил и упрощает устранение неполадок, не влияя на выполнение правил.
    Action: Добавьте содержательные комментарии ко всем правилам HA, чтобы облегчить их последующее обслуживание и аудит.
  3. СредняяНовая опция --disable для команд HA‑rule.
    --disable <boolean> может использоваться для включения (false) или отключения (true) правила HA без его удаления.
    Impact: Позволяет временно приостановить правило, сокращая необходимость в его повторном создании и минимизируя дрейф конфигурации.
    Action: Используйте «--disable true», чтобы приостановить правило во время обслуживания, и включите его обратно с помощью «--disable false», когда работа завершена.
  4. НизкаяПо умолчанию аффинити установлено в положительное.
    Если флаг «--affinity» не указан, система теперь предполагает положительную аффинность, сохраняя обратную совместимость с более ранними версиями, где было возможно только положительное размещение.
    Impact: Существующие скрипты, которые опускают флаг, продолжат вести себя как раньше, но администраторам следует учитывать подразумеваемое значение по умолчанию.
    Action: Явно указывайте «--affinity» в скриптах автоматизации, чтобы избежать неоднозначности.
  5. НизкаяОбновлена справка CLI и man‑страницы для параметров HA‑rule.
    В справке командной строки и в руководствах теперь перечислены новые параметры (--affinity, --comment, --disable) и уточнено поведение по умолчанию.
    Impact: Операторы получают точные указания напрямую из CLI, уменьшая вероятность ошибочной конфигурации.
    Action: Запустите «pve-ha-manager --help» или обратитесь к обновлённым справочным страницам после обновления.
