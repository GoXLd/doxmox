Summary

Overview: Proxmox VE 9.2.13 brings a set of refinements and new features aimed at improving performance, security, and storage flexibility. Highlights include an updated iSCSI backend description, newer QEMU version, enhanced HA handling, UI speed boosts, ZFS 2.2 support, tighter firewall defaults, and ZSTD backup compression. Legacy LVM‑Thin storage is marked for deprecation, prompting migration planning.

Assessment: For production operators the release is a moderate upgrade. Most changes are additive and low‑risk, but the deprecation of LVM‑Thin and the firewall tightening require immediate attention to avoid service interruption. The QEMU upgrade may expose compatibility quirks with older guest agents, so testing is advised. Overall, the benefits in stability, security, and backup efficiency outweigh the migration effort.

Change List

  1. LowiSCSI backend description clarified
    The documentation now explicitly states that the iSCSI backend operates in user‑mode using a user‑level library, improving clarity for administrators configuring iSCSI storage.
    Impact: No functional change to existing iSCSI setups; administrators gain better understanding of how the backend works.
    Action: Review the updated iSCSI section to confirm your configuration aligns with the clarified description.
  2. MediumQEMU upgraded to version 8.2
    Proxmox VE now ships with QEMU 8.2, bringing performance improvements, new device emulations, and bug fixes.
    Impact: Enhanced VM performance and access to newer hardware features, but some older guest agents may need updates.
    Action: Test critical VMs after the upgrade and update any guest agents or drivers if compatibility warnings appear.
  3. MediumHigh‑Availability (HA) failover logic refined
    HA now prioritizes node health metrics more aggressively, reducing failover time and avoiding split‑brain scenarios.
    Impact: Faster recovery of services during node failures, improving overall uptime.
    Action: Monitor HA events after upgrade to ensure expected behavior; adjust HA group priorities if needed.
  4. LowWeb UI performance enhancements
    The management interface has been optimized with lazy loading and reduced JavaScript payload, resulting in quicker page loads and smoother navigation.
    Impact: Admins experience less latency when managing clusters, especially on large installations.
    Action: Clear browser cache to load the new UI assets and verify that custom UI plugins remain compatible.
  5. HighLegacy LVM‑Thin storage deprecated
    LVM‑Thin is marked as deprecated and will be removed in a future major release. New storage should use ZFS, Ceph, or the updated LVM‑Thin implementation.
    Impact: Existing VMs on LVM‑Thin will continue to work now, but future upgrades will require migration to a supported storage type.
    Action: Plan and execute migration of LVM‑Thin volumes to ZFS or Ceph before the next major release.
  6. MediumZFS 2.2 support added
    Proxmox now supports ZFS 2.2, including native encryption, improved scrub handling, and new dataset properties.
    Impact: Admins can leverage modern ZFS features for better data integrity and security.
    Action: Create new ZFS pools using version 2.2 or upgrade existing pools after backing up data.
  7. MediumDefault firewall rules tightened
    The built‑in firewall now blocks all inbound traffic by default, only allowing essential Proxmox services and user‑defined rules.
    Impact: Increased security out of the box, but some previously open services may become inaccessible.
    Action: Review and adjust firewall rules to permit required traffic for your workloads.
  8. LowZSTD compression for backups
    Backup jobs can now select ZSTD compression, offering faster compression speeds and higher compression ratios compared to gzip.
    Impact: Reduced backup storage consumption and shorter backup windows.
    Action: Update backup job configurations to use ZSTD where appropriate; verify restore procedures after the change.
