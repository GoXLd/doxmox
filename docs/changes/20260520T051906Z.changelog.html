Summary

Overview: Proxmox VE 9.1.5 introduces several important updates that affect storage, networking, firewall, and system defaults. The changes aim to improve performance, security, and ease of configuration while adding new features like BGP integration and FastEC support.

Assessment: The release balances new capabilities with tighter defaults. Notable are the reduced ZFS ARC footprint, which helps multi‑VM hosts, and the introduction of FastEC, which can boost erasure‑coded pool performance but requires careful planning. Network operators will benefit from expanded BGP/SDN options, yet must adjust firewall rules for Ceph and migration traffic. Overall risk is moderate; most changes are additive, but the FastEC flag is irreversible without pool recreation.

Change List

  1. LowVersion bump to 9.1.5
    Documentation and release metadata updated to version 9.1.5 with a new release date.
    Impact: Ensures users reference the correct documentation and receive the latest bug fixes.
    Action: Verify you are consulting the 9.1.5 docs for any configuration tasks.
  2. MediumZFS ARC default reduced
    Default ARC size changed from 50% of host memory to 10%, capped at 16 GiB. The setting is written to /etc/modprobe.d/zfs.conf during installation for Proxmox VE 8.1+.
    Impact: Reduces memory pressure on hosts running many VMs, improving overall stability.
    Action: Monitor ARC usage; adjust /etc/modprobe.d/zfs.conf if a larger cache is required for heavy ZFS workloads.
  3. HighCeph firewall port reminder
    Documentation now explicitly states that the firewall must allow Ceph traffic ports. Use the provided firewall macro for easy configuration.
    Impact: Unopened ports can break Ceph cluster communication, leading to data unavailability.
    Action: Enable the Ceph firewall macro or manually open the required ports (e.g., 6789, 6800‑7300).
  4. MediumFastEC (allow_ec_optimizations) documentation added
    Introduces a new flag to enable fast erasure‑coded I/O paths. Requires EC pools, recent monitor releases, and stripe units aligned to 4096 bytes. The flag is one‑way; clearing it requires pool recreation.
    Impact: Potential performance boost for EC pools, but may trigger primary re‑election and cancel ongoing scrubs.
    Action: Test FastEC on a non‑production pool first, then enable via 'pveceph set allow_ec_optimizations=1' if results are satisfactory.
  5. LowPG autoscaler CRUSH rule consistency requirement
    Autoscaler now requires all pools to use the same type of CRUSH rule (either device class or none).
    Impact: Mixed rule types can cause autoscaler failures or uneven data distribution.
    Action: Standardize CRUSH rules across pools before enabling the autoscaler.
  6. MediumBGP configuration expanded under SDN
    New sections cover fabric‑level and node‑level BGP options, including IPv4/IPv6 prefixes, BFD, route maps, redistribution sources, and support for unnumbered interfaces. EVPN underlay requires at least one IPv4 address per node.
    Impact: Enables advanced routing for multi‑site clusters but adds configuration complexity.
    Action: Follow the step‑by‑step BGP guide; start with a simple IPv4 setup before adding advanced features.
  7. LowLoad balancer default thresholds updated
    Imbalance threshold now defaults to 30 % and imbalance improvement to 10 %, with values normalized to a 0‑100 scale.
    Impact: Improves automatic load distribution decisions out of the box.
    Action: Review and adjust thresholds if your workload requires tighter balancing.
  8. LowSysctl configuration moved to drop‑in file
    System‑wide rp_filter setting is now applied via /etc/sysctl.d/99-rp-filter.conf instead of editing /etc/sysctl.conf directly.
    Impact: Simplifies sysctl management and aligns with best practices for package upgrades.
    Action: Confirm the drop‑in file exists and contains the desired settings; reload sysctl with 'sysctl --system'.
