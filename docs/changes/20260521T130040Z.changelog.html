Summary

Overview: Proxmox VE 9.2.1 introduces several important updates: default Ceph manager type switched to "tentacle", new HA auto‑rebalance settings, expanded OSPF and OpenID options, CPU level parameter for custom models, regex enhancements, and cleanup of deprecated backup settings. Documentation has been enriched with examples and clearer wording.

Assessment: The release tightens cluster stability by preventing accidental removal of critical Ceph components and by adding auto‑rebalance for HA resources. Network routing and authentication configurations gain flexibility, while the removal of obsolete options reduces configuration drift. Operators should review the new defaults and adjust monitoring to capture the changed behavior.

For newcomers: This update makes Proxmox easier to use and safer. Some default names have changed, new options let you balance workloads automatically, and the help files now show step‑by‑step examples. If you follow the recommended actions, your servers will keep running smoothly.

Change List

  1. Ceph manager default type changed to "tentacle"
    The default manager daemon type is now "tentacle" instead of the legacy "squid". Existing clusters keep their current manager type unless explicitly changed.
    Impact: New installations will deploy the newer, more efficient manager. Scripts that assume "squid" may need adjustment.
    Action: Verify any automation that references the manager type and update it to accept "tentacle" as the default.
    Severity: low
  2. HA auto‑rebalance option added
    A boolean "auto-rebalance" flag (default enabled) allows the HA scheduler to move resources automatically when node load changes.
    Impact: Resources can migrate without manual intervention, improving uptime, but may cause brief service moves during load spikes.
    Action: Monitor HA logs after the first few rebalances to ensure workloads behave as expected; disable the flag if you need strict placement control.
    Severity: medium
  3. OSPF "Redistribute" configuration introduced
    A new "Redistribute" entry lets administrators specify which routes (static, connected, etc.) should be advertised into OSPF.
    Impact: Provides finer control over routing announcements, reducing unwanted traffic leaks.
    Action: Add explicit redistribute rules for each OSPF area to match your network policy.
    Severity: medium
  4. CPU model UI now supports "level" parameter
    When defining a custom CPU model, a "level" argument can be set to expose additional CPU flags, including those required for recent Windows guests.
    Impact: Improves compatibility for VMs needing newer instruction sets without exposing the full host CPU.
    Action: Review existing custom CPU definitions and add the appropriate level value where needed.
    Severity: low
  5. Regex patterns now allow newline (0x0A) characters
    Entry point and environment variable validation regexes have been updated to accept line‑feed characters, enabling multi‑line values.
    Impact: Facilitates more complex scripts and configuration blocks directly in the UI.
    Action: Test any multi‑line entries to confirm they are accepted; no further changes required.
    Severity: low
  6. Backup "maxfiles" option deprecated and removed
    The "maxfiles" setting, which limited the number of retained backup files, is no longer supported. Retention is now managed via the "prune-backups" schedule.
    Impact: Existing configurations using "maxfiles" will fall back to default retention behavior.
    Action: Update backup jobs to use the "prune-backups" schedule for retention control.
    Severity: medium
  7. ZFS blocksize description clarified
    Documentation now explicitly states that blocksize must be a power‑of‑two value with an optional suffix (K, M, G).
    Impact: Reduces configuration errors when creating ZFS volumes.
    Action: Verify any custom ZFS blocksize settings conform to the new description.
    Severity: low
  8. OpenID "--audiences" option added with regex validation
    A new "--audiences" flag allows specifying accepted token audiences; input is validated against an extended regex pattern.
    Impact: Enhances security by restricting which tokens are accepted for authentication.
    Action: Configure the appropriate audience values for your identity provider and test login flows.
    Severity: high
