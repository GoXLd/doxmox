Summary

Overview: Proxmox VE 9.2.1 introduces several important updates: the default Ceph manager backend switches from squid to tentacle, new CPU model options and level settings are added, regex handling now accepts newline characters, and documentation for container ID mapping and UID/GID handling is expanded. Additional operational tweaks include HA auto‑rebalance, updated OSPF options, refined backup settings, and a new node location property.

Assessment: The changes are largely backward‑compatible but affect cluster configuration scripts and automation. Operators should review Ceph manager defaults to avoid unexpected manager type changes, adjust any custom CPU model definitions to include the new level field, and verify that regex‑based filters still behave as intended now that LF characters are permitted. HA and networking tweaks improve resilience but may require parameter tuning. Overall, the release raises the feature set without breaking existing deployments, provided the recommended actions are followed.

Change List

  1. ●Ceph manager default changed to tentacle
    The default manager backend for new Ceph clusters is now "tentacle" instead of the older "squid" implementation.
    Impact: Existing clusters remain unchanged, but newly created clusters will use tentacle, which offers better performance and future feature support.
    Action: When creating a new Ceph cluster, verify the manager type if you rely on specific squid features, or explicitly set the manager type to squid if needed.
  2. ●New CPU model "level" option
    A "level" parameter has been added to cpu-models.conf, allowing fine‑grained selection of CPU feature sets (e.g., level 1‑5). Several new model names such as ClearwaterForest‑v2, DiamondRapids, and SapphireRapids‑v6 have also been added.
    Impact: Custom CPU model definitions that omit the level may fall back to defaults, potentially affecting VM performance or compatibility.
    Action: Review any custom cpu-models.conf entries and add an appropriate level value; test VMs after changes to ensure expected behavior.
  3. ●Regex patterns now accept newline (\x0a)
    Entry point and environment variable regexes have been updated to allow the line‑feed character, enabling multi‑line values.
    Impact: Scripts that previously rejected newline characters will now accept them, which can simplify passing complex data.
    Action: Validate existing regex‑based filters to ensure they still match intended inputs; adjust patterns if unintended matches appear.
  4. ●Expanded container ID mapping documentation
    The documentation now includes additional examples and clearer paragraphs for UID/GID mapping inside containers.
    Impact: Operators gain better guidance, reducing misconfiguration risk when mapping host IDs to containers.
    Action: Read the updated docs and apply the example mappings to any custom container setups.
  5. ●HA auto‑rebalance option added
    A boolean "auto-rebalance" flag (default true) is now available for HA resources, allowing the cluster to automatically move resources for better load distribution.
    Impact: Clusters may experience automatic migrations after node failures or load spikes, improving uptime.
    Action: Enable or disable auto‑rebalance per your policy; monitor HA logs after enabling to confirm expected behavior.
  6. ●Node location property (--location) introduced
    Nodes can now be tagged with geographic coordinates (latitude, longitude) and an optional name via the new "--location" property.
    Impact: Facilitates location‑aware scheduling and reporting, but requires updating node configuration if you use location‑based policies.
    Action: Add location data to each node using "pve node set --location <lat>,<lon>,<name>" where relevant.
  7. ●Backup configuration cleanup
    The deprecated "maxfiles" option has been removed from backup job settings; backup jobs now rely on retention policies only.
    Impact: Existing backup jobs that still reference maxfiles will fail to parse.
    Action: Edit affected backup jobs to remove the maxfiles line and configure retention via "maxfiles"‑style policies if needed.
  8. ●ZFS blocksize description clarified
    The blocksize parameter now explicitly states it must be a power of two with optional 'k' or 'm' suffix (e.g., 4k, 8m).
    Impact: Improves user input validation; incorrect values will be rejected with clearer error messages.
    Action: Verify any custom ZFS storage definitions use the new syntax; adjust scripts that generate blocksize values accordingly.

Overview: Proxmox VE 9.2.1 introduit plusieurs mises à jour importantes : le backend du gestionnaire Ceph par défaut passe de squid à tentacle, de nouvelles options de modèle CPU et de paramètres de niveau sont ajoutées, la gestion des expressions régulières accepte désormais les caractères de nouvelle ligne, et la documentation sur le mappage des ID de conteneur ainsi que la gestion UID/GID est étendue. Change List

  1. ●Le gestionnaire Ceph par défaut a été changé en tentacle
    Le backend du gestionnaire par défaut pour les nouveaux clusters Ceph est désormais « tentacle » au lieu de l’ancienne implémentation « squid ».
    Impact: Les clusters existants restent inchangés, mais les clusters nouvellement créés utiliseront tentacle, qui offre de meilleures performances et un support des futures fonctionnalités.
    Action: Lors de la création d’un nouveau cluster Ceph, vérifiez le type de gestionnaire si vous comptez sur des fonctionnalités spécifiques de squid, ou définissez explicitement le type de gestionnaire sur squid si nécessaire.
  2. ●Nouvelle option « level » du modèle CPU
    Un paramètre « level » a été ajouté à cpu-models.conf, permettant une sélection granulaire des ensembles de fonctionnalités CPU (par ex., niveau 1‑5). Plusieurs nouveaux noms de modèles tels que ClearwaterForest‑v2, DiamondRapids et SapphireRapids‑v6 ont également été ajoutés.
    Impact: Les définitions de modèle CPU personnalisées qui omettent le niveau peuvent revenir aux valeurs par défaut, ce qui peut affecter les performances ou la compatibilité des VM.
    Action: Examinez toutes les entrées personnalisées de cpu-models.conf et ajoutez une valeur de niveau appropriée ; testez les VMs après les modifications pour garantir le comportement attendu.
  3. ●Les modèles Regex acceptent désormais le saut de ligne (\x0a)
    Les expressions régulières du point d'entrée et des variables d'environnement ont été mises à jour pour autoriser le caractère de saut de ligne, permettant des valeurs multi‑lignes.
    Impact: Les scripts qui rejetaient auparavant les caractères de nouvelle ligne les accepteront désormais, ce qui peut simplifier le passage de données complexes.
    Action: Validez les filtres existants basés sur les regex pour vous assurer qu'ils correspondent toujours aux entrées prévues ; ajustez les motifs si des correspondances inattendues apparaissent.
  4. ●Documentation étendue du mappage des ID de conteneur
    La documentation inclut désormais des exemples supplémentaires et des paragraphes plus clairs pour le mappage UID/GID à l'intérieur des conteneurs.
    Impact: Les opérateurs bénéficient d’une meilleure orientation, réduisant le risque de mauvaise configuration lors du mappage des ID d’hôte aux conteneurs.
    Action: Lisez la documentation mise à jour et appliquez les correspondances d’exemple à toutes les configurations de conteneurs personnalisées.
  5. ●Option d'auto‑rééquilibrage HA ajoutée
    Un drapeau booléen « auto-rebalance » (valeur par défaut true) est désormais disponible pour les ressources HA, permettant au cluster de déplacer automatiquement les ressources afin d’améliorer la répartition de la charge.
    Impact: Les clusters peuvent subir des migrations automatiques après des pannes de nœuds ou des pics de charge, améliorant le temps de disponibilité.
    Action: Activez ou désactivez l'auto‑rebalance selon votre politique ; surveillez les journaux HA après l'activation pour confirmer le comportement attendu.
  6. ●Propriété d'emplacement du nœud (--location) introduite
    Les nœuds peuvent désormais être étiquetés avec des coordonnées géographiques (latitude, longitude) et un nom optionnel via la nouvelle propriété « --location ».
    Impact: Facilite la planification et le reporting sensibles à la localisation, mais nécessite la mise à jour de la configuration du nœud si vous utilisez des politiques basées sur la localisation.
    Action: Ajoutez des données de localisation à chaque nœud avec « pve node set --location <lat>,<lon>,<name> » lorsque pertinent.
  7. ●Nettoyage de la configuration de sauvegarde
    L'option « maxfiles » obsolète a été supprimée des paramètres des tâches de sauvegarde ; les tâches de sauvegarde s'appuient désormais uniquement sur les politiques de rétention.
    Impact: Les jobs de sauvegarde existants qui font encore référence à maxfiles échoueront à l'analyse.
    Action: Modifiez les tâches de sauvegarde concernées pour supprimer la ligne maxfiles et configurez la rétention via des politiques de type « maxfiles » si nécessaire.
  8. ●Description du blocksize ZFS clarifiée
    Le paramètre blocksize indique désormais explicitement qu'il doit être une puissance de deux avec un suffixe optionnel « k » ou « m » (par ex., 4k, 8m).
    Impact: Améliore la validation des entrées utilisateur ; les valeurs incorrectes seront rejetées avec des messages d’erreur plus clairs.
    Action: Vérifiez que toutes les définitions de stockage ZFS personnalisées utilisent la nouvelle syntaxe ; ajustez les scripts qui génèrent les valeurs de blocksize en conséquence.
