Summary

Overview: Proxmox VE 9.1.3 introduces a range of enhancements and clarifications aimed at simplifying cluster management, improving storage and networking flexibility, and strengthening high‑availability (HA) controls. The release also updates documentation to reflect new best‑practice procedures for node removal, QDevice handling, and secure boot certificate management.

Assessment: The update delivers solid incremental value for production environments. Notable are the refined HA auto‑rebalance options, clearer Ceph network change procedures, and the addition of the import storage type, which together reduce operational risk. Documentation improvements around node removal and QDevice prerequisites help prevent common pitfalls. Overall risk is low, but operators should review the new HA and Ceph steps before applying them in critical clusters.

For newcomers: This version adds helpful new features and clearer instructions. You’ll see a newer UI element (scroll‑to‑top), more storage choices, better guidance for safely removing a node, and new safety checks when changing network settings. If you run HA or Ceph, there are extra options to keep your services running smoothly.

Change List

  1. Version bump and UI polish
    Proxmox VE is now version 9.1.3. A "scroll to top" link was added to the documentation pages, and minor wording updates improve clarity across the UI description.
    Impact: Users see the new version number and benefit from easier navigation in the docs.
    Action: Refresh the web UI and documentation cache to view the latest UI elements.
    Severity: low
  2. Enhanced node removal workflow with QDevice warning
    New documentation requires removal of any QDevice before taking a node out of the cluster and adds a detailed step‑by‑step guide for safe removal, especially for Ceph‑enabled nodes.
    Impact: Prevents cluster quorum loss and Ceph data inconsistency during node decommissioning.
    Action: Verify QDevice status, follow the new removal checklist, and ensure all VMs and storage are migrated before proceeding.
    Severity: high
  3. Ceph network change procedures clarified
    A comprehensive new section (8.13.5) explains how to modify public and cluster networks, including MTU testing, IPv4/IPv6 packet size limits, and required service restarts.
    Impact: Reduces risk of accidental cluster downtime when adjusting network settings.
    Action: Follow the step‑by‑step guide, test MTU sizes, and restart OSDs one host at a time as described.
    Severity: medium
  4. HA auto‑rebalance options introduced
    New HA configuration flags (ha-auto-rebalance, ha-auto-rebalance-method, etc.) allow automatic redistribution of resources after failures, with customizable thresholds and hold durations.
    Impact: Improves resilience and reduces manual intervention for HA clusters.
    Action: Enable ha-auto-rebalance in the HA manager and tune the method and thresholds to match your workload.
    Severity: medium
  5. Import storage type added
    Documentation now includes an "import" storage type, allowing direct import of external data sets into Proxmox storage pools.
    Impact: Simplifies migration of existing data without needing intermediate steps.
    Action: Create an import storage definition where needed and use the pvesm import commands to bring data in.
    Severity: low
  6. Secure Boot certificate expiration handling
    New guidance on Microsoft Secure Boot certificates (2023k, 2023w) and how to enroll updated keys, including CLI commands for certificate renewal.
    Impact: Prevents boot failures on systems with expired Secure Boot certificates.
    Action: Check the current certificate version on each node and run the provided enrollment commands if needed.
    Severity: high
  7. CPU model list expanded and defaults clarified
    The supported CPU model list now includes newer AMD EPYC and Intel Sapphire/Rapids generations, and the default CPU type is set to "host" architecture.
    Impact: Ensures optimal performance on modern hardware and reduces manual CPU configuration.
    Action: Verify that VMs use the default "host" CPU model unless a specific compatibility mode is required.
    Severity: low
  8. Migration downtime parameter capped
    The "migration-downtime" option now has a maximum of 2000 seconds, matching QEMU's limit.
    Impact: Prevents configuration errors that could cause migration failures.
    Action: Adjust any custom migration-downtime values to stay within the new limit.
    Severity: low
  9. CLI option "--max-workers" replaces deprecated "--maxworkers"
    A new "--max-workers" flag (1‑64) is introduced with clearer defaults; the old "--maxworkers" flag is deprecated.
    Impact: Provides better control over parallel operations and aligns with newer configuration standards.
    Action: Update scripts and automation to use "--max-workers" and remove references to the deprecated flag.
    Severity: low
  10. HA manager commands for arm/disarm HA
    New commands "crm-command arm-ha" and "crm-command disarm-ha" allow administrators to temporarily disable HA during maintenance, with options to freeze or ignore resources.
    Impact: Facilitates safe cluster maintenance without triggering HA failovers.
    Action: Use "disarm-ha" before planned maintenance and "arm-ha" afterwards, selecting the appropriate resource mode.
    Severity: medium
