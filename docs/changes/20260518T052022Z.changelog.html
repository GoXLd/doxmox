Summary

Overview: Proxmox VE 9.1.4 introduces several documentation and feature updates that improve security, storage handling, networking, and high‑availability scheduling. The changes range from new guidance on cluster CA distribution to detailed ZFS encryption rules, added WireGuard and EVPN controller information, and enhancements to the Cluster Resource Scheduler (CRS). Operators will find new flags for token regeneration and SSH‑based cluster joins, while newcomers benefit from clearer explanations of networking constructs like Prefix Lists and Route Maps.

Assessment: The release adds substantive security and HA improvements that require attention during upgrade planning. ZFS encryption enforcement and CRS load‑balancer parameters can impact workload placement and must be reviewed before production rollout. New documentation on EVEVPN, WireGuard, and idmap storage options expands the feature set, offering more flexibility but also increasing configuration complexity. Overall, the update is a net positive for stability and security, provided operators validate the new settings in a test environment.

For newcomers: If you are new to Proxmox, this version gives you clearer steps to set up a secure cluster, explains how to protect ZFS disks with encryption, and introduces easy‑to‑read guides for advanced networking like WireGuard and EVPN. It also tells you how the system decides where to run your virtual machines, so you can keep your services running smoothly.

Change List

  1. ●Version bump to 9.1.4
    Documentation now reflects the new Proxmox VE version 9.1.4 and updates the last‑modified timestamp.
    Impact: Ensures all references point to the correct version, avoiding confusion during support or upgrade processes.
    Action: Verify that your environment matches the documented version; no functional changes required.
  2. ●Manual distribution of the cluster CA file
    Added a paragraph describing how to copy the cluster CA certificate to new nodes manually, since there is no API endpoint for this operation.
    Impact: Operators must ensure the CA file is present on each node to maintain secure inter‑node communication.
    Action: Copy the CA file to /etc/pve/cluster/ca.pem on each new node before joining the cluster.
  3. ●pvecm add default API authentication and --use_ssh flag
    The pvecm add command now defaults to API‑based authentication, removing the need for SSH passwords. A new --use_ssh flag allows legacy SSH joins.
    Impact: Simplifies cluster expansion while still supporting older workflows.
    Action: Use the default pvecm add command for new nodes; add --use_ssh only when required for compatibility.
  4. ●ZFS encryption documentation
    Introduces a dedicated ZFS Encryption subsection covering encryption_root, migration constraints, and the requirement that all storages be encrypted when using this feature.
    Impact: Provides clear guidance to protect data at rest; misconfiguration could prevent VM migration or backup.
    Action: Review the encryption settings before enabling ZFS encryption and test migration of encrypted volumes.
  5. ●idmap option added to storage definitions
    The idmap parameter is now documented for various storage types, allowing per‑mount ID mapping configuration.
    Impact: Enables finer control over UID/GID translation for containers and VMs, improving compatibility with mixed‑user environments.
    Action: Add idmap settings where needed in storage.cfg; verify container access after changes.
  6. ●EVPN controller documentation enhancements
    Renamed sections to Primary Controller and Additional Controllers, added ASN requirements, and introduced new fields (Nodes, Peer Group Name, BGP Mode, ebgp‑multihop).
    Impact: Clarifies multi‑controller setups and BGP configuration, reducing misconfiguration risk.
    Action: Follow the updated guide when configuring EVPN; ensure all controllers share the same ASN.
  7. ●WireGuard configuration guide added
    Comprehensive documentation for WireGuard fabric, node roles, interfaces, peers, route generation, key handling, and required packages.
    Impact: Expands secure overlay networking options for operators.
    Action: Read the new WireGuard section before deploying; install the wireguard package on all nodes.
  8. ●Prefix Lists and Route Maps documentation
    New sections explain syntax, sequence numbers, actions, ge/le qualifiers, reserved names, and provide usage examples.
    Impact: Helps operators create precise routing policies within SDN.
    Action: Use the examples as templates when building your own prefix lists and route maps.
  9. ●Cluster Resource Scheduler (CRS) mode and load‑balancer parameters
    Added CRS Scheduling Mode (basic, static‑load, dynamic‑load) and detailed load‑balancer settings such as imbalance threshold, hold duration, and rebalancing method.
    Impact: Directly influences HA resource placement and migration decisions; incorrect values can cause unnecessary migrations or resource starvation.
    Action: Review and adjust CRS settings in Datacenter → Options to match your workload characteristics; test in a staging cluster.
  10. ●API token regeneration flag (--regenerate)
    Introduces a new flag for the Update API token command that creates a new secret and invalidates the old one; the new token cannot be retrieved later.
    Impact: Improves security by allowing token rotation, but requires careful handling to avoid loss of access.
    Action: Save the regenerated token immediately; update any scripts or services that use the token.
  11. ●Serial device regex update
    The device pattern for --serial options changed from "/dev/.+" to "/dev/[^,]+" to prevent commas in device paths from being accepted.
    Impact: Reduces parsing errors when specifying serial devices.
    Action: Ensure serial device paths do not contain commas; no further action needed for existing configurations.

Summary

Overview: Proxmox VE 9.1.4 introduit plusieurs mises à jour de la documentation et des fonctionnalités qui améliorent la sécurité, la gestion du stockage, le réseau et la planification de haute disponibilité. Les changements vont d’une nouvelle orientation sur la distribution du CA du cluster à des règles détaillées de chiffrement ZFS, en passant par l’ajout d’informations sur WireGuard et le contrôleur EVPN, ainsi que des améliorations du Cluster Resource Scheduler (CRS). Les opérateurs trouveront de nouveaux indicateurs pour la régénération de jetons et les jointures de cluster basées sur SSH, tandis que les nouveaux utilisateurs bénéficieront d’explications plus claires des constructions réseau telles que les listes de préfixes et les cartes de routage.

Assessment: La version ajoute des améliorations substantielles de sécurité et de HA qui nécessitent une attention particulière lors de la planification de la mise à jour. L'application du chiffrement ZFS et les paramètres du load‑balancer CRS peuvent impacter le placement des charges de travail et doivent être examinés avant le déploiement en production. La nouvelle documentation sur EVEVPN, WireGuard et les options de stockage idmap élargit le jeu de fonctionnalités, offrant plus de flexibilité mais augmentant également la complexité de la configuration. Dans l’ensemble, la mise à jour est globalement positive pour la stabilité et la sécurité, à condition que les opérateurs valident les nouveaux paramètres dans un environnement de test.

For newcomers: Si vous êtes nouveau sur Proxmox, cette version vous fournit des étapes plus claires pour configurer un cluster sécurisé, explique comment protéger les disques ZFS avec le chiffrement, et propose des guides faciles à lire pour le réseau avancé tel que WireGuard et EVPN. Elle indique également comment le système détermine où exécuter vos machines virtuelles, afin que vous puissiez maintenir vos services en bon fonctionnement.
