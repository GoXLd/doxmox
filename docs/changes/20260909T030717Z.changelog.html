Summary

Overview: This release updates the Proxmox Ceph integration documentation and tools. It removes outdated key‑ring copy instructions, renumbers several sections, adds a health‑check mute feature, introduces a migration path from AES to AES‑256‑K for CephX keys, provides a helper utility for the migration, and adds a new CLI command to view key status. Operators get clearer guidance and new safety mechanisms; newcomers see a more streamlined learning path.

Assessment: The documentation overhaul improves operational clarity and reduces the risk of mis‑configuration. The most critical change is the AES‑256‑K migration, which addresses CVE‑2025‑30156 and strengthens cluster security. The mute health‑check feature aids alert management but must be used carefully to avoid hiding real issues. Overall, the release balances security hardening with usability enhancements, making it a net positive for production environments.

Change List

  1. LowRemoval of outdated key‑ring copy example
    The documentation no longer includes the `mkdir /etc/pve/priv/ceph … cp …` snippet that was previously used to copy Ceph key‑rings manually.
    Impact: Operators who followed the old guide may need to adjust their scripts; the new process relies on the automated migration helper.
    Action: Review any custom automation that uses the removed commands and replace them with the new helper tool or standard Ceph key management commands.
  2. LowSection renumbering for CephFS and Ceph Maintenance
    All subsections under CephFS and Ceph Maintenance have been incremented by one level (e.g., CephFS 8.12 → 8.13, Ceph Maintenance 8.13 → 8.14).
    Impact: Links or bookmarks to specific sections may break.
    Action: Update internal documentation or scripts that reference the old section numbers.
  3. MediumNew "Mute a Health Check" feature
    Introduces `ceph health mute <CHECK> <duration>` (e.g., `2w`) and a UI workflow (Datacenter → Ceph → Mute/Unmute). Includes a `--sticky` option to keep the mute active even when new items appear.
    Impact: Allows operators to silence non‑critical alerts temporarily, reducing noise in monitoring dashboards.
    Action: Use the mute command or UI only for alerts that are understood and being addressed elsewhere; always document the mute duration and reason.
  4. HighMigration of CephX keys from AES to AES‑256‑K
    Adds a dedicated section explaining why health checks appear after upgrading to Ceph Squid 19.2.6 / Tentacle 20.2.4 and outlines the security rationale (CVE‑2025‑30156).
    Impact: Clusters using older AES ciphers are vulnerable; migration is required to maintain compliance and security.
    Action: Plan and execute the key‑migration using the provided helper tool; verify that all clients support AES‑256‑K before applying.
  5. MediumCephX key‑migration helper utility
    New documentation covers staged keys, confirmation flags, abort procedures, emergency cipher override, and recovery steps. Key flags include `--apply`, `--confirm‑all‑clients‑refreshed`, `--confirm‑clients‑refreshed <USER>`, `--abort‑staged‑key <USER> --apply`, and `--confirm‑abort‑clients‑refreshed <USER> --apply`.
    Impact: Provides a safe, automated way to transition keys without service interruption, but misuse can lock out clients.
    Action: Run the helper in a test environment first, follow the step‑by‑step checklist, and ensure you have backups of existing key files (`/etc/pve/priv/ceph/*.keyring`, `*.secret`).
  6. LowNew CLI command `pveceph auth status`
    Displays current CephX key ciphers and reports any prerequisites for the AES‑256‑K migration. Supports standard format options for scripting.
    Impact: Operators can quickly verify migration readiness and audit key status across the cluster.
    Action: Integrate `pveceph auth status` into health‑check scripts and run it before starting the migration process.
  7. MediumEmergency Cipher Override configuration
    Introduces the `mon_auth_emergency_allowed_ciphers` setting and its interaction with `AUTH_EMERGENCY_CIPHERS_SET` to allow temporary fallback to weaker ciphers during migration emergencies.
    Impact: Provides a safety valve if a migration fails, but using weaker ciphers reduces security temporarily.
    Action: Only enable the override in a controlled emergency; revert to the default cipher set as soon as the migration completes.
