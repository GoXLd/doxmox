Overview: Proxmox VE 9.2.2 documentation has been updated with a version bump, clarified networking endpoint fields, and revised support lifecycle information. The changes improve configuration accuracy and set clear expectations for product support timelines.

Assessment: The documentation refinements reduce the risk of misconfiguring WireGuard endpoints and align support statements with Debian security policies. Operators should verify existing configurations against the new examples and adjust monitoring of support dates accordingly.

  1. LowVersion bump to Proxmox VE 9.2.2

    Impact: Ensures users reference the correct version when following guides, preventing version‑specific mismatches.
    Action: Confirm you are running Proxmox VE 9.2.2 or later before applying the documented steps.
  2. MediumExpanded description of the internal node Endpoint field
    The Endpoint field now includes concrete examples (e.g., `192.0.2.1`, `2001:db8::1`) and clarifies that it combines with the interface's Listen Port to form the full endpoint string such as `192.0.2.1:51820`.
    Impact: Reduces ambiguity when configuring internal WireGuard peers, leading to fewer connection failures.
    Action: Update any existing endpoint entries to match the new format and verify the associated Listen Port is correctly set.
  3. MediumClarified behavior of the internal node Endpoint Port field
    Removed the vague “defaults to …” wording. The documentation now states that the port is taken directly from the interface’s Listen Port and shows how the final endpoint string is built.
    Impact: Prevents accidental use of unintended ports, improving network reliability.
    Action: Check that each interface’s Listen Port matches the intended endpoint port and adjust if necessary.
  4. HighExternal peer Endpoint format requires IP/hostname and port together
    External endpoints must now be written as `IP:port` (e.g., `192.0.2.1:51820`). For IPv6, the address must be wrapped in brackets, e.g., `[2001:db8::1]:51820`.
    Impact: Incorrect endpoint strings will cause immediate connection failures with external peers.
    Action: Review all external peer configurations and rewrite them using the new combined syntax, especially for IPv6 entries.
  5. LowSupport lifecycle paragraph re‑phrased
    The text now emphasizes that Proxmox VE is supported at least as long as the underlying Debian release is maintained by the Debian Security Team, roughly three years.
    Impact: Provides clearer expectations for long‑term maintenance and upgrade planning.
    Action: Align your upgrade schedule with the Debian release lifecycle to maintain support coverage.
  6. MediumSupport table end‑of‑support month updated
    The end‑of‑support month for the current release has been changed from 2026‑08 to 2026‑07.
    Impact: Shortens the official support window by one month, affecting planning for patches and upgrades.
    Action: Adjust your support and upgrade timelines to reflect the new 2026‑07 end‑of‑support date.
