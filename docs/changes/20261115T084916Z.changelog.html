Summary

Overview: Proxmox VE documentation has been updated to version 9.2.14, introducing clearer guidance on NUMA allocation policies, a revamped match‑rule syntax, updated password‑hashing recommendations, and several clarifications that affect both new users and seasoned operators.

Assessment: The changes are largely backward‑compatible but introduce new configuration options that can improve performance and security when used correctly. Operators should review the new match‑expression JSON format and the invert rule to avoid unintended rule behavior. The shift to Yescrypt for password hashing strengthens credential security, and the clarified NUMA policies help optimize VM placement on multi‑socket hosts.

Change List

  1. LowExpanded NUMA allocation policy documentation
    The NUMA policy field now lists the accepted values (preferred, bind, interleave) and links to the kernel documentation for each mode.
    Impact: Operators can now configure VM memory placement more precisely, reducing latency on multi‑socket servers.
    Action: Review existing VM configurations and, where appropriate, set the desired NUMA policy to match workload requirements.
  2. MediumInvert rule added to match‑rule nodes
    Each match‑rule node can now include an "invert" flag, allowing the rule to match when the condition is *not* met.
    Impact: Provides greater flexibility in defining when notifications, migrations, or other actions should trigger.
    Action: Audit existing match rules and consider using the invert flag to simplify complex rule sets.
  3. HighIntroduction of match‑expression JSON format
    A new JSON‑based syntax replaces the older match‑field, match‑calendar, and match‑severity options. The JSON supports constant, field, severity, calendar, all‑of, any‑of, one‑of, and not nodes.
    Impact: Offers a more expressive and machine‑readable way to define match conditions, but old syntax remains functional until the next major release.
    Action: Begin migrating existing match configurations to the JSON format; test the new syntax in a staging environment before production rollout.
  4. MediumDeprecation notice for legacy match options
    The previous match‑field, match‑calendar, and match‑severity parameters are now marked as deprecated and will be removed in a future major version.
    Impact: Configurations that rely on these legacy options will continue to work for now but will require updating before the next major release.
    Action: Convert all legacy match definitions to the new JSON format to avoid future breakage.
  5. HighPassword hashing recommendation updated to Yescrypt
    Documentation now recommends using Yescrypt for storing passwords, providing stronger resistance to brute‑force attacks compared to the older SHA‑256 method.
    Impact: Improves overall system security for user authentication.
    Action: Update any custom authentication scripts or policies to generate Yescrypt hashes; re‑hash existing passwords if feasible.
  6. LowClarified default behavior of notification matchers
    When no match rules are defined, notification matchers now explicitly state that they will always evaluate to true, ensuring predictable alerting behavior.
    Impact: Prevents accidental suppression of notifications due to missing rule definitions.
    Action: Verify that all critical alerts have appropriate match rules; rely on the default true behavior only where intentional.
  7. LowRemoval of experimental unprivileged mknod note
    The previous documentation reference to an experimental unprivileged mknod feature has been removed, reflecting its stable integration into the kernel.
    Impact: Reduces confusion for operators about the maturity of the feature.
    Action: No action required; the feature can now be used without special caveats.

Summary

Overview: Документация Proxmox VE обновлена до версии 9.2.14, в ней представлены более чёткие рекомендации по политикам распределения NUMA, обновлённый синтаксис match‑rule, актуализированные рекомендации по хешированию паролей и несколько уточнений, влияющих как на новых пользователей, так и на опытных операторов.

Assessment: Изменения в основном совместимы с предыдущими версиями, но вводят новые параметры конфигурации, которые при правильном использовании могут улучшить производительность и безопасность. Операторам следует изучить новый формат JSON для match‑expression и правило invert, чтобы избежать непреднамеренного поведения правил. Переход на Yescrypt для хеширования паролей усиливает безопасность учётных данных, а уточнённые политики NUMA помогают оптимизировать размещение VM на многосокетных хостах.
